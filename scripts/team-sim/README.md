# 团队版五台实测（`npm run test:team`）

一条命令把桌面端团队版从注册到移除成员走一遍，每一步都有断言（2026-10-04，上线前测试 4.1）。
单测只有一台真客户端，这里是 6 个真进程：一个本机云端（托管模式 + 中转）+ 5 台桌面端本地服务（和 Electron 里跑的同一个 `desktop/server-bundle`），每台配一个模拟壳，照真壳前台的节奏每 8 秒戳一次 `/api/desktop/sync`。

## 怎么跑

```bash
npm run test:team
```

- **要多久**：约 1 分钟（本机 M 系列，实测 55–70 秒）。`desktop/server-bundle` 比 `src/`、`prisma/`、`migrations/` 旧（或还没有）时会先自动 `cd desktop && npm run build:server`（含 `next build`），再加 1 分钟左右。
- **端口**：云端 3520，5 台 3521–3525。被占了就 `TEAM_SIM_PORT=3620 npm run test:team`。
- **数据**：全在系统临时目录 `team-sim-*` 里（各台自己的 crm.db / .cloud.json / .team.json，云端的 control.db / sync），跑完不管红绿都按进程号关掉起过的进程、删掉临时目录。要留现场看完整日志和库：`TEAM_SIM_KEEP=1`。
- 其它开关：`TEAM_SIM_SEED`（老板先录几位客户，默认 30）、`TEAM_SIM_BUILD=1` 强制重新装配 / `=0` 不管新旧直接用现有产物。

## 断言了什么（超时就红）

1. 5 个云端账号注册、登录拿设备令牌（每人一个 `x-forwarded-for`，绕开同 IP 一天 3 个的上限）；各台自动登录、选模版
2. 老板先录 30 位客户 / 60 条跟进 → 建团队 → 运营台开通 → 等老板那台把老数据推上云（真实情况开通是人工的、分钟级，同事加入时老数据早在云上）→ 4 人凭邀请码加入，成员名单和角色对
3. **最后一位加入后 15 秒内** 5 台客户数、跟进数、团队账号数一致；每台本机角色对（老板 ADMIN、业务员 SALES）
4. 4 位业务员各写一位客户 + 一条跟进 → **老板 10 秒内**在客户列表和客户页上看到
5. 业务员 A 的客户列表、跟进页、直接打开客户页都看不到业务员 B 的客户（先确认 B 的客户已经同步进 A 的库，才算数）
6. 同一位客户：两台同时改不同字段两边都留；同一字段两台几乎同时改，后改的赢（来回各一次）
7. 老板放一位进公海 → 业务员在公海页看到 → 领取 → 其余各台负责人变成他、出了公海
8. 老板移除一人 → 其余各台自动换钥匙（钥匙编号变大）并继续收到新数据；被移出那台自动退出团队、只剩自己的客户、收不到新数据，他那台的清理没有传给别人

动作都走 HTTP：改数据调的是界面按钮背后的同一个 Server Action（从构建产物的 `server-reference-manifest.json` 按「文件 + 导出名」找编号，清单在 `actions.mjs`，`tests/team-sim-actions.test.ts` 在平常的 vitest 里钉着它们还在），「看得到 / 看不到」看的是那台的页面。只有「每台都有全队数据」这类界面上本来就看不到的事才只读打开库核对。

红了会打印：哪一步、哪台、期望、实际，以及那台模拟壳最近几轮的同步结果、`.team.json` 里的 lastError、本地服务和云端的日志尾巴。
同步没成但下一轮补上的轮次不判红，跑完列在「观察」里。等待类断言超时后会再看 20 秒，红的时候分得清是「慢了，第几秒才到」还是「根本没到」。

**已知偶发红**（约十来次一次）：「业务员在公海里看到（10 秒内）」这类 10 秒断言报「慢了」。原因在产品里不在脚本：写库正赶上本机一轮同步在跑时，「改完 1.5 秒就推」会被吞掉（lib/team-scope.ts 改完推一下 遇到 __同步中 直接返回；计时到点时上一轮没跑完，同步一轮() 直接复用那一轮），改动要等壳的下一轮才推，同事最长约 16 秒才看到。修好之前别把 10 秒放宽。
