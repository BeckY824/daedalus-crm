# 网站要对接的东西

桌面端和应用里有几处写死的对外地址，官网改版时不能动它们，否则装出去的客户端会静默失灵。
这一篇就是那份清单，外加各部分代码在哪。

## 一、官网必须提供的两样

### 1. `https://ai-daedalus.com/download.html`

下载页。桌面端「检查更新」发现新版时打开的就是它（`desktop/updater.js` 里的 `下载页`），
`latest.json` 不带 `url` 时也回落到它。

页面上至少要有：

- Mac（Apple 芯片）的 dmg 下载链接
- **放行 Gatekeeper 的步骤**。第一次打开一定会被系统拦，说明不写清楚的话这批人就流失在这一步。
  文案直接抄 [桌面端安装.md](桌面端安装.md) 的「装」一节
- 一句「只有 Apple 芯片版」。Intel Mac 现在没有包

### 2. `https://ai-daedalus.com/desktop/latest.json`

版本信息。桌面端每天自动查一次，也可以手动查。三个字段：

```json
{
  "version": "0.15.0",
  "url": "https://ai-daedalus.com/download.html",
  "notes": "这一版改了什么，会原样显示在提示框里"
}
```

- `version` 只看前三段数字，`v` 前缀可有可无
- 这个文件**优先级高于 GitHub Release**。改它就能立刻让所有客户端看到新版，
  适合控制放量；不想管它就别放，桌面端会自动回落到 GitHub
- 兜底源：`https://api.github.com/repos/BeckY824/daedalus-crm/releases/latest`，
  用 `tag_name` 当版本号。打 tag 时 CI 会把 dmg 挂上去，所以通常自动就是对的

> 注意：官网的部署脚本是**白名单**的。新增这两个文件要同时加进
> 官网仓库 `deploy/build.sh` 的 `FILES` 数组，否则不会被发到线上。

## 二、官网不能删的一页

`https://ai-daedalus.com/demo.html`

应用内有两处链到它：演示区的门口（没有演示码时「到这里申请」）和试用横条的按钮。
改版可以改内容，但**路径要留着**，或者同步改
`src/app/demo/DemoGate.tsx` 与 `src/components/DemoBar.tsx`。

## 三、官网该往哪里送人

| 按钮 | 送到哪 | 说明 |
|---|---|---|
| 下载桌面端 | `/download.html` | 装完就能用，不需要注册 |
| 注册账号 | `https://app.ai-daedalus.com/signup` | 手机号或邮箱 + 验证码。桌面端现在**不能注册**，只能登录，所以想用 AI 的人要先到这里注册 |
| 在线演示 | `https://app.ai-daedalus.com/demo` | v0.14.0 起需要演示码，官网按钮旁边要说明这一点 |
| 用户协议 | `https://app.ai-daedalus.com/terms` | 页面在应用里，官网页脚直接链过去即可 |
| 隐私政策 | `https://app.ai-daedalus.com/privacy` | 同上 |
| 自部署 | `https://github.com/BeckY824/daedalus-crm` | 开源版，docker compose 一条命令 |

## 四、桌面端连云端的地址

桌面端只在两件事上连云端：登录账号、调模型。地址写死在 `desktop/cloud.js`：

```
https://app.ai-daedalus.com/api/account/token       POST 发令牌 / DELETE 吊销
https://app.ai-daedalus.com/api/gateway/v1/models   可用模型
https://app.ai-daedalus.com/api/gateway/v1/credits  还剩几次
https://app.ai-daedalus.com/api/gateway/v1/chat/completions
```

换域名的话这里和 `desktop/main.js` 的 `默认服务器` 要一起改。
联调时用环境变量覆盖：`CRM_CLOUD_URL`、`CRM_URL`、`CRM_UPDATE_URL`。

## 五、代码在哪

CRM 仓库（就是这个仓库），下面的路径都相对仓库根目录：

| 路径 | 是什么 |
|---|---|
| `desktop/main.js` | Electron 主进程：窗口、菜单、本地/服务器模式切换 |
| `desktop/local-server.js` | 在用户机器上拉起随包发布的服务 |
| `desktop/server-entry.js` | 打进安装包的服务入口：首次建库、补迁移 |
| `desktop/cloud.js` | 云端账号：登录、退出、查额度、把令牌交给本地服务 |
| `desktop/updater.js` | 检查更新（只查不装） |
| `desktop/sign.js` | ad-hoc 签名。Apple 芯片上不签会报「已损坏」 |
| `desktop/scripts/build-server.mjs` | 把 CRM 装配成随包发布的服务 |
| `desktop/server-bundle/` | 装配产物，不进版本库 |
| `desktop/dist/` | 安装包，不进版本库 |
| `src/app/api/gateway/v1/` | 模型网关 |
| `src/app/api/account/token/` | 发/吊销设备令牌 |
| `src/app/api/desktop/session/` | 本地模式的自动登录 |
| `src/lib/tenant/credits.ts` | AI 免费次数账本（工作区与账号共用一套规则） |
| `src/lib/tenant/device-token.ts` | 设备令牌 |
| `src/lib/gateway.ts` | 网关配置与请求体清洗 |
| `docs/桌面端安装.md` | 面向使用者的安装说明 |
| `desktop/README.md` | 桌面端的实现与取舍 |

官网是另一个仓库（静态站）：

| 路径 | 是什么 |
|---|---|
| `*.html` | 页面源文件，`en/` 是英文站 |
| `deploy/build.sh` | 打包到 `dist/`。**白名单**，新页面要加进 `FILES` |
| `deploy/deploy.sh` | 发布脚本，rsync 到官网服务器 |

> 服务器地址、登录方式、部署目录都不写进这个仓库——它是公开的。那些在运维笔记里。

使用者机器上的数据：`~/Library/Application Support/DaedalusCRM/`
（`data/crm.db` 业务数据、`data/.cloud.json` 云端令牌、`logs/server.log` 服务日志）。

## 六、发一版桌面端的完整步骤

1. 在 Apple 芯片的 Mac 上：`cd desktop && npm install && npm run dist:mac`
   （首次要手动 `node node_modules/electron/install.js`，本机 npm 禁用了安装脚本）
2. 产物在 `desktop/dist/*.dmg`
3. 打 tag 推上去，CI 会自己打包并把 dmg 挂到同名 GitHub Release
4. 更新官网的 `desktop/latest.json` 与 `download.html` 上的链接，跑 `deploy/deploy.sh`
5. 装出来自己走一遍：清掉 `~/Library/Application Support/DaedalusCRM` 再打开，
   应该是建库 → 自动进主界面
