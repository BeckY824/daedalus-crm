# 托管版

自部署的人不用看这一篇。这里写的是我们自己运营的那套：陌生人注册、试用 7 天、
到期只读、我们手动或自动开通。

开源版默认就是单租户，不开 `MULTI_TENANT` 时下面这些代码一行都不会执行。

## 怎么开

```bash
MULTI_TENANT=1
CONTROL_DATABASE_URL=file:/data/control.db
WORKSPACE_DIR=/data/ws
ADMIN_TOKEN=<一串长随机字符串>
```

外加验证码通道（都可选，没配的那种就把验证码打到日志里，`docker compose logs crm | grep '\[verify\]'`）：

```bash
# 手机号注册：阿里云短信
SMS_ACCESS_KEY_ID=...
SMS_ACCESS_KEY_SECRET=...
SMS_SIGN_NAME=...
SMS_TEMPLATE_CODE=...
# 邮箱注册：任何 SMTP（阿里云邮件推送、腾讯云 SES、企业邮箱）
SMTP_HOST=smtpdm.aliyun.com
SMTP_PORT=465
SMTP_USER=...
SMTP_PASS=...
SMTP_FROM="Daedalus CRM <no-reply@你的域名>"
```

条款页（`/terms`、`/privacy`）里的运营主体和联系邮箱可用 `LEGAL_ENTITY`、`LEGAL_CONTACT` 覆盖。

### 官网预约演示表单（`POST /api/lead`，0.18.0 起）

官网 `demo.html` 填完直接 POST 到这里，服务器用上面同一条 SMTP 把内容发到我们邮箱，
`Reply-To` 是访客邮箱，在收件箱里点「回复」就是回给客户。SMTP 没配时接口回 503，官网自动落回
「复制内容 / 打开邮件客户端」的兜底面板，所以不配也不会丢客户，只是回到从前。

| 变量 | 默认 | 说明 |
|---|---|---|
| `LEAD_TO` | `LEGAL_CONTACT`，再没有就是 README 里的邮箱 | 线索发到哪个收件箱 |
| `LEAD_ORIGINS` | 空 | 除官网外还允许哪些来源跨域调用，逗号分隔；本地调官网时填 `http://localhost:8080` 之类 |

不需要凭证但会花邮件额度，所以有四道闸（在 `src/lib/lead.ts`）：只认官网的 `Origin`、蜜罐字段、
每 IP 每天 5 条、全站每天 50 条。发失败的那次不占额度。刻意不入库——要看历史线索去收件箱。

## 模型网关

桌面端把数据留在用户自己机器上，唯一还需要云端的就是模型调用——用户没有自己的
API Key，我们替他转发，并按**账号**扣免费次数（网页端是按工作区扣，规则同一份，
见 `lib/tenant/credits.ts`）。

```bash
GATEWAY_API_KEY=...                    # 上游（中转站）的 Key，缺它整个网关 404
GATEWAY_BASE_URL=https://.../v1        # 上游地址，默认 DeepSeek 官方
GATEWAY_MODELS="deepseek-v4.1-flash"   # 白名单，第一个是默认
```

对外是标准的 OpenAI 兼容接口，所以桌面端的 AI 设置就是「接口地址填我们、Key 填设备令牌」：

| 接口 | 干什么 |
|---|---|
| `GET /api/account/policy` | 这个部署开着哪两条路：网页那边还收不收新注册、能不能自助找回 |
| `POST /api/account/code` | 发**找回密码**的验证码邮件（注册用的码不从这里发） |
| `POST /api/account/password` | 验证码 + 新密码 → 改密（规则和网页 `/forgot` 是同一份） |
| `POST /api/account/token` | 手机号/邮箱 + 密码 → 一枚长期设备令牌（只存 sha256） |
| `POST /api/gateway/v1/chat/completions` | 扣一次额度再转发给上游，支持流式 |
| `GET /api/gateway/v1/models` | 白名单模型 |
| `GET /api/gateway/v1/credits` | 还剩几次 |

**桌面端不能在应用内注册。** 登录页上的「注册新账号 ↗」是 `shell.openExternal` 到网页
`/signup`，注册整个在网页上办。中间试过在桌面端直接开「只有账号、没有工作区」的号
（数据在用户机器上，给他建个空库确实没意义），2026-09-15 否掉了：
那种账号进不了网页版（没有工作区，登录被挡下），而同一个邮箱又注册不了第二次——
一个账号在两个地方行为不一样，比多点一次浏览器糟得多。

找回密码留在桌面端里（`/api/account/code` + `/api/account/password`）：
那时账号已经存在，没有上面那个问题。

**模型白名单不是可选的。** 网关花的是我们的钱，一次调用扣一次账，但不同模型的
成本能差两个数量级——不限的话，一个改了 `model` 字段的请求就能把免费额度花在最贵的那个上。

额度在**转发之前**扣，失败的那次也算：限的是"发起"而不是"成功"，
否则一个反复失败的请求可以无限重试，而每次重试都是真金白银的上游调用。

## 数据长什么样

两类库，严格分开：

| 库 | 位置 | 装什么 |
|---|---|---|
| 控制面 | `/data/control.db` | 账号、工作区、成员、验证码、邀请、试用与订阅状态、AI 次数账本、桌面端令牌 |
| 业务库 | `/data/ws/<slug>.db` | 一个工作区的全部客户与跟进，与其它工作区互不可见 |
| 模板 | `/data/ws/_template.db` | 空业务库，开新工作区时直接复制 |

隔离的全部依据就是「一个工作区一个文件」。所以控制面不存业务数据，业务库不存账号。

备份把 `/data` 整个打包即可，两类库都在里面。

## 租户是怎么路由的

业务代码里的 `prisma` 是个代理，**在每次方法调用时**按当前会话解析出工作区，
再用那个工作区的客户端执行。34 处 import 一个都没改。

为什么是「调用时」而不是「取属性时」，以及为什么没用 AsyncLocalStorage 或
React 的 `cache()`，见 `src/lib/tenant/resolve.ts` 顶部的注释——两条路都实测走不通，
结论写在那里了。

解析不到工作区时直接抛错，不会静默落到默认库。宁可 500 也不能串库。

## 注册

手机号或邮箱 + 密码 + 团队名，勾选用户协议和隐私政策（服务端也验）。

**默认不要验证码。** 验证码证明的是「这个号是你的」，代价是必须先有一条发码通道，
而通道要等——短信签名要备案、邮件要域名验证。为这个把注册挡在门外换来的安全性并不值：
这是个 7 天试用的 CRM，不是银行。代价写明白：联系方式可能是假的，
一个人也可以多开几个号薅免费 AI 次数——后者由「每个 IP 每天最多 3 个」兜着。
通道配好后把 `SIGNUP_VERIFY=1` 打开就恢复验证，代码不用动。

密码至少 8 位、必须同时含字母和数字。不验证手机号的时候，它是唯一一道门。
**没有任何码。** 开号只有注册这一条路，进演示区也不要码——整套码（一次性激活码、万能邀请码、演示码）
2026-09-15 下线。它们挡住的主要是想看看的人，而真要薅额度的人换个浏览器就绕过去了；
代价是「怎么才能开号」有了好几个说法，而这件事应该只有一个说法。
防刷：临时邮箱域名不给发码；同一出口 IP 每天最多开 3 个工作区。

### 关掉自助注册 / 加上验证码

`SIGNUP_REDIRECT` 指向一个地址就等于关掉自助注册：`/signup` 跳走，两个 Server Action 也一律拒绝。

想在注册时加一道验证码，就配一条发码通道并打开 `SIGNUP_VERIFY=1`。
这两个脚本会一起做掉（写 .env、删掉 SIGNUP_REDIRECT、打开验证、重启、带你验证一次）：

```bash
./enable-email-signup.sh smtpdm.aliyun.com 465 no-reply@mail.你的域名 '密码' 'Daedalus CRM <no-reply@mail.你的域名>'
./enable-sms-signup.sh <AccessKeyId> <AccessKeySecret> <签名> <模板CODE>
```

两个可以都配：填的像手机号走短信，像邮箱走 SMTP。

**手机号那条现在办不下来**：代码走的是阿里云国内短信（`dysmsapi.aliyuncs.com`，
RegionId `cn-hangzhou`），而国内短信签名要求域名已备案；我们的服务器在香港、域名没备案。
这是流程卡点，不是代码问题。想通就得先有一台大陆服务器去备案。
邮箱那条不受这个限制，当天就能通。

## 找回密码

`/forgot`：填注册时的邮箱 → 收一个 6 位验证码 → 设新密码。登录页的「忘记密码？」指向它。

**要配了 SMTP 才出现。** 没配通道时 `sendCode` 会降级成「把码打进服务端日志」——
那对注册尚可（运维能从日志里把码捞给用户），对找回密码是个死胡同：人对着空收件箱等，
而我们并不知道他在等。所以这条路整个不出现，页面直说请联系我们。判据在
`src/lib/tenant/password-reset.ts`，自部署版（没有 `MULTI_TENANT=1`）同样不出现——
那边改密是管理员在「设置 → 团队成员」里的事。

**只认邮箱。** 手机号那条要短信，原因同注册一节。早年用手机号注册的账号只能找我们人工重置。

**桌面端也能改。** 它走 `/api/account/code` + `/api/account/password`，
规则和网页是同一份（`lib/tenant/password-reset.ts`）。注意改完密码**不会**
顺手吊销设备令牌：令牌是另一类凭证（像应用专用密码），有它自己的吊销口子；
绑进改密里会变成「在网页上改个密码，手上三台机器的 AI 全断了」而没人知道为什么。

**不能拿它查号。** 没注册过的邮箱也返回同一句成功，连「刚发过了」的节流行为都一致
（所以不存在的号也照样存一条码，只是不发信）。区分开的话，这就是一个查我们客户名单的接口。

**改完密码，之前签出去的会话全部作废。** 会话是一张签了 7 天的 JWT，服务端不存它也就删不掉它；
只换密码的话，拿着旧 Cookie 的那个人还能再用一周。补法是控制面多一张 `SessionCutoff`：
记下这个账号最后一次改密的时刻，票据的 `iat` 早于它就不认。

这一道在两个地方各有一份：`resolveCurrentTenant`（数据面——`prisma.ts` 直接问它要工作区，
旧票据连库都开不了；那里有 10 秒缓存，最坏晚 10 秒生效）和 `getCurrentUser`（页面面——
不走缓存，改完立刻把别的设备踢下线）。少哪一份都漏一类入口。
都不放在 `proxy.ts`——那里跑在 Edge 运行时，连不了控制面库。
顺带把这个账号的登录限流也清掉：会走到这一页的人多半刚把密码试错到冷却，
不清的话他拿着刚设好的新密码还要再等 5 分钟。

## AI 免费次数

试用期的 AI 对话按工作区记一本赠送账（控制面 `AiGrant` 表）：注册送 30 次；余额不足 30 时，
当天有使用就再送 3 次（一天一次，按北京时间）。付费后不限。
余额 = 赠送之和 − `AiUsage.calls`，被拦下的那次会减回去。运营台每个工作区有「AI +10」。

## 试用与到期

试用 7 天，从注册那一刻算。AI 次数和天数是两条线：到期后 AI 也一并停掉。到期后**只读**：能看、能导出，不能新增和修改。
闸门在 `prisma` 代理里，写方法和裸 SQL 都拦——Server Action 是公开端点，
靠前端隐藏按钮拦不住。

到期不删数据。数据一直留着，付费后立刻恢复。

## 开通订阅

现在是人工的：用户在 `/billing` 看价格、转账、填单号，我们在 `/admin` 核对后点开通。
一天就能上线，也足够验证有没有人真的愿意付。扫码支付等微信商户号下来再接。

续费在原到期日上顺延，不从今天重算——重算会吃掉用户已经付过的天数。

### 别对线上控制面库跑 `npm run control:push`

那条命令是 `prisma db push`，会把库对齐到当前 schema——而 `ActivationCode` /
`DemoCode` / `TrialMasterCode` 已经不在 schema 里了，**它会把这三张表连数据一起删掉**。
线上走的是 `docker-entrypoint.sh` 里的裸 SQL（`control-schema.sql` + `control-migrations/*.sql`，
只加表不改表），不经过 Prisma 的 push。`control:push` 只给本地开发用。

## 运营台

`https://<域名>/admin?token=<ADMIN_TOKEN>`

能看所有工作区、谁提交了付款、AI 次数余额，能开通、延长试用 7 天、AI +10、停用、手动开工作区。

这里原来还挂着三块码（万能邀请码、演示码、一次性邀请码）和一个 `POST /api/admin/codes`，
2026-09-15 整套下线。要给谁多送几次 AI，用「AI +10」那个按钮更直接，也不用先发一个码出去。
线上那三张表**留着不删**（删表不可逆，几张空表不花什么钱），但代码里再也碰不到它们。
它不属于任何工作区，所以不走应用的登录体系，用独立 token 保护；
每个动作都会重新验一遍 token（Server Action 是独立端点，页面那次校验拦不住直接调用）。

没配 `ADMIN_TOKEN` 时这个页面返回 404，自部署的人不会暴露一个无保护的后台。

## 加了新表之后

容器每次启动会：重建模板库、给 `/data/ws/` 下所有存量业务库补跑 `migrations/`。
所以新增表结构照常写进 `migrations/NNN-xxx.sql`，规矩不变：**只能加，且要幂等**
（迁移每次启动都整个重跑一遍，`ALTER TABLE` 第二次就会让容器起不来）。
