# 托管版

自部署的人不用看这一篇。这里写的是我们自己运营的那套：陌生人注册、试用 7 天、
到期只读、我们手动或自动开通。

开源版默认就是单租户，不开 `MULTI_TENANT` 时下面这些代码一行都不会执行。

## 怎么开

```bash
MULTI_TENANT=1
CONTROL_DATABASE_URL=file:/data/control.db
WORKSPACE_DIR=/data/ws
ADMIN_TOKEN=<一串长随机字符串>
```

外加验证码通道（都可选，没配的那种就把验证码打到日志里，`docker compose logs crm | grep '\[verify\]'`）：

```bash
# 手机号注册：阿里云短信
SMS_ACCESS_KEY_ID=...
SMS_ACCESS_KEY_SECRET=...
SMS_SIGN_NAME=...
SMS_TEMPLATE_CODE=...
# 邮箱注册：任何 SMTP（阿里云邮件推送、腾讯云 SES、企业邮箱）
SMTP_HOST=smtpdm.aliyun.com
SMTP_PORT=465
SMTP_USER=...
SMTP_PASS=...
SMTP_FROM="Daedalus CRM <no-reply@你的域名>"
```

条款页（`/terms`、`/privacy`）里的运营主体和联系邮箱可用 `LEGAL_ENTITY`、`LEGAL_CONTACT` 覆盖。

## 模型网关

桌面端把数据留在用户自己机器上，唯一还需要云端的就是模型调用——用户没有自己的
API Key，我们替他转发，并按**账号**扣免费次数（网页端是按工作区扣，规则同一份，
见 `lib/tenant/credits.ts`）。

```bash
GATEWAY_API_KEY=...                    # 上游（中转站）的 Key，缺它整个网关 404
GATEWAY_BASE_URL=https://.../v1        # 上游地址，默认 DeepSeek 官方
GATEWAY_MODELS="glm-5.3-flash|限时免费,deepseek-chat"   # 白名单，第一个是默认
```

对外是标准的 OpenAI 兼容接口，所以桌面端的 AI 设置就是「接口地址填我们、Key 填设备令牌」：

| 接口 | 干什么 |
|---|---|
| `POST /api/account/token` | 手机号/邮箱 + 密码 → 一枚长期设备令牌（只存 sha256） |
| `POST /api/gateway/v1/chat/completions` | 扣一次额度再转发给上游，支持流式 |
| `GET /api/gateway/v1/models` | 白名单模型 |
| `GET /api/gateway/v1/credits` | 还剩几次 |

**模型白名单不是可选的。** 网关花的是我们的钱，一次调用扣一次账，但不同模型的
成本能差两个数量级——不限的话，一个改了 `model` 字段的请求就能把免费额度花在最贵的那个上。

额度在**转发之前**扣，失败的那次也算：限的是"发起"而不是"成功"，
否则一个反复失败的请求可以无限重试，而每次重试都是真金白银的上游调用。

## 数据长什么样

两类库，严格分开：

| 库 | 位置 | 装什么 |
|---|---|---|
| 控制面 | `/data/control.db` | 账号、工作区、成员、验证码、邀请、试用与订阅状态、AI 次数账本、桌面端令牌 |
| 业务库 | `/data/ws/<slug>.db` | 一个工作区的全部客户与跟进，与其它工作区互不可见 |
| 模板 | `/data/ws/_template.db` | 空业务库，开新工作区时直接复制 |

隔离的全部依据就是「一个工作区一个文件」。所以控制面不存业务数据，业务库不存账号。

备份把 `/data` 整个打包即可，两类库都在里面。

## 租户是怎么路由的

业务代码里的 `prisma` 是个代理，**在每次方法调用时**按当前会话解析出工作区，
再用那个工作区的客户端执行。34 处 import 一个都没改。

为什么是「调用时」而不是「取属性时」，以及为什么没用 AsyncLocalStorage 或
React 的 `cache()`，见 `src/lib/tenant/resolve.ts` 顶部的注释——两条路都实测走不通，
结论写在那里了。

解析不到工作区时直接抛错，不会静默落到默认库。宁可 500 也不能串库。

## 注册

手机号或邮箱 + 密码 + 团队名，勾选用户协议和隐私政策（服务端也验）。

**默认不要验证码。** 验证码证明的是「这个号是你的」，代价是必须先有一条发码通道，
而通道要等——短信签名要备案、邮件要域名验证。为这个把注册挡在门外换来的安全性并不值：
这是个 7 天试用的 CRM，不是银行。代价写明白：联系方式可能是假的，忘了密码没法自助找回
（只能到运营台重置），一个人也可以多开几个号薅免费 AI 次数——后者由「每个 IP 每天最多 3 个」兜着。
通道配好后把 `SIGNUP_VERIFY=1` 打开就恢复验证，代码不用动。

密码至少 8 位、必须同时含字母和数字。不验证手机号的时候，它是唯一一道门。
邀请码可选：预约演示后我们发的**万能码**（一个、可反复用、运营台一键更换）或旧的一次性码都认，填了多送 AI 次数。
防刷：临时邮箱域名不给发码；同一出口 IP 每天最多开 3 个工作区。

### 关掉自助注册 / 加上验证码

`SIGNUP_REDIRECT` 指向一个地址就等于关掉自助注册：`/signup` 跳走，两个 Server Action 也一律拒绝。

想在注册时加一道验证码，就配一条发码通道并打开 `SIGNUP_VERIFY=1`。
这两个脚本会一起做掉（写 .env、删掉 SIGNUP_REDIRECT、打开验证、重启、带你验证一次）：

```bash
./enable-email-signup.sh smtpdm.aliyun.com 465 no-reply@mail.你的域名 '密码' 'Daedalus CRM <no-reply@mail.你的域名>'
./enable-sms-signup.sh <AccessKeyId> <AccessKeySecret> <签名> <模板CODE>
```

两个可以都配：填的像手机号走短信，像邮箱走 SMTP。

**手机号那条现在办不下来**：代码走的是阿里云国内短信（`dysmsapi.aliyuncs.com`，
RegionId `cn-hangzhou`），而国内短信签名要求域名已备案；我们的服务器在香港、域名没备案。
这是流程卡点，不是代码问题。想通就得先有一台大陆服务器去备案。
邮箱那条不受这个限制，当天就能通。

## AI 免费次数

试用期的 AI 对话按工作区记一本赠送账（控制面 `AiGrant` 表）：注册送 30 次；余额不足 30 时，
当天有使用就再送 3 次（一天一次，按北京时间）；填了邀请码多送 50 次。付费后不限。
余额 = 赠送之和 − `AiUsage.calls`，被拦下的那次会减回去。运营台每个工作区有「AI +10」。

## 试用与到期

试用 7 天，从注册那一刻算。AI 次数和天数是两条线：到期后 AI 也一并停掉。到期后**只读**：能看、能导出，不能新增和修改。
闸门在 `prisma` 代理里，写方法和裸 SQL 都拦——Server Action 是公开端点，
靠前端隐藏按钮拦不住。

到期不删数据。数据一直留着，付费后立刻恢复。

## 开通订阅

现在是人工的：用户在 `/billing` 看价格、转账、填单号，我们在 `/admin` 核对后点开通。
一天就能上线，也足够验证有没有人真的愿意付。扫码支付等微信商户号下来再接。

续费在原到期日上顺延，不从今天重算——重算会吃掉用户已经付过的天数。

## 运营台

`https://<域名>/admin?token=<ADMIN_TOKEN>`

能看所有工作区、谁提交了付款、AI 次数余额，能开通、延长试用 7 天、AI +10、停用。
下面三块码：万能邀请码（更换）、演示码（生成 10 个，进 `/demo` 用，一码一个浏览器、5 次 AI）、一次性邀请码。
命令行也能生成：`POST /api/admin/codes`，header `x-admin-token`，body `{"kind":"master"|"demo"|"once","count":10}`。
它不属于任何工作区，所以不走应用的登录体系，用独立 token 保护；
每个动作都会重新验一遍 token（Server Action 是独立端点，页面那次校验拦不住直接调用）。

没配 `ADMIN_TOKEN` 时这个页面返回 404，自部署的人不会暴露一个无保护的后台。

## 加了新表之后

容器每次启动会：重建模板库、给 `/data/ws/` 下所有存量业务库补跑 `migrations/`。
所以新增表结构照常写进 `migrations/NNN-xxx.sql`，规矩不变：**只能加，且要幂等**
（迁移每次启动都整个重跑一遍，`ALTER TABLE` 第二次就会让容器起不来）。
