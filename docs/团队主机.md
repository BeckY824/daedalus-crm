# 团队主机：几个人共用一份数据

几个人要看同一份客户，有两条路：

| | 团队主机（这一页） | 团队同步（桌面端「设置 → 团队」） |
|---|---|---|
| 数据在哪 | 团队里一台常开的机器上，一份 | 每人电脑上各一份，加密后经我们的中转互相同步，我们只见得到密文 |
| 要装什么 | 一台机器跑 Docker | 什么都不用装，要开通 |
| 离线能用吗 | 不能，连不上主机就用不了 | 能，联网后自动同步 |
| AI | 用主机上配的 Key | 用桌面端自带的 |
| 提醒（Dock 数字、早报、到点）、MCP | 不工作（见文末） | 照常 |

适合团队主机的：在一个办公室、有一个人愿意管一台机器。下面是步骤。

## ① 选一台主机

办公室里一台不关机的机器就行：群晖 / 威联通 NAS（Container Manager）、Mac mini、或一台常开的 Windows（装 Docker Desktop）。

不在一处办公，可以租一台国内的云服务器（2 核 2G 够用）。

## ② 起服务

照 [部署.md](部署.md) 起一个自部署实例：

```bash
docker compose up -d
```

国内拉 `ghcr.io` 慢或不通时，把 `docker-compose.yml` 里的 image 换成镜像站地址；还不通就找我们要一个镜像包，`docker load` 进去。

## ③ 开账号

浏览器开 `http://<主机 IP>:3000`，`admin` / `admin123` 登录，**立刻改密码**。然后：

- 设置 → 团队成员：给每人建一个账号
- 设置 → AI 接入：填一个 AI Key（DeepSeek 等，几个人一个月几块钱）。桌面端注册送的 AI 次数在这条路上用不上

## ④ 每人连上

每人在桌面端：**设置 → 桌面端 → 连接服务器**，填 `http://192.168.x.x:3000`，用第 ③ 步的账号登录。

想回到自己电脑上那份私人数据：应用菜单「改用本机数据」。两份并存，互不影响。

## ⑤ 不在一个地方

不要把 3000 端口直接开到公网（明文传输）。两种做法：

- 装一个加密的虚拟局域网（如开源的 EasyTier），大家填虚拟 IP。不用域名
- 团队有自己的域名：照 [部署.md](部署.md)「加 HTTPS」叠一层 Caddy

## ⑥ 备份

主机上每天跑一次 `./scripts/backup.sh`（放进 cron）。恢复和异地存一份，见 [部署.md](部署.md)「备份与恢复」。

## ⑦ 各人原来的数据

- 各人本机已有的客户：本机那份「客户 → 导出」，团队那份「客户 → 导入」。**只带客户，跟进记录带不过去**
- 只有一个人有历史数据：可以把他的本机备份整库恢复到主机当底（`restore.sh`），再用 `RESET_PASSWORDS=1` 重设各人密码

## 连着主机时，桌面端少了什么

- **提醒**：Dock 上的数字、早报、到点提醒只看本机数据，连着主机时不提醒
- **MCP**（让 Claude Code / Codex 查 CRM）：桌面端那个固定端口只答本机数据，连着主机时它会直接说「现在连着服务器」，不答——免得把你的私人数据当成团队的答出去。要让 agent 查团队那份：在主机网页的「设置 → AI 接入」里开 MCP，照那里给的地址和令牌接（主机要能从你这台电脑访问到）
- **设置 → 桌面端** 那一栏（备份、数据文件夹）：主机网页里没有。切回本机数据才看得到
