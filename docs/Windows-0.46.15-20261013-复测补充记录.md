# Windows 0.46.15 修复候选复测补充（2026-10-13）

E2/E3 清单中的账号切换已完成：旧通知在切换后消失，新账号没有进入老板资料；由于旧通知已被关闭，迟到点击无法实际触发，只能判定“关闭旧通知”通过。普通通知与到点提醒的实际点击仍未跳转，导航验收失败。`shown` 后迅速 `banner-closed`，仅凭日志不能确定关闭原因。`0x80000003` 的根因也仍未定位。

F2 老板私客查询的实际回答：“当前可访问范围内未找到匹配记录（0 条）；记录可能不存在，也可能无权访问，无法据此区分。”业务员自有 `QA-SAM-member2-private` 查询返回 1 条、正确手机号和负责人。本地服务的浏览器界面显示 5 位客户；只读 SQL 看到 `Customer` 共 13 条，其中业务员负责 5 条、老板负责 8 条。界面过滤有效，不等于端侧 SQLite 没有私客记录；是否违反设计需开发核实。

启动补充：旧候选完整 QA 副本首次带固定端口 58502 启动，命中 Windows 保留端口范围并报 `listen EACCES`；仅移走副本中的 `.port` 后正常打开。另一次经工具终端启动独立业务员实例出现 `unknown software exception (0x80000003)`，地址 `0x00007FF63A980E6C`，日志记载本地服务启动超时。随后用户从文件资源管理器运行同一隔离实例正常打开。因此工具终端异常不计作正常桌面冷启失败，也不能据此确定和历史 0x80000003 同根因。未发现新的 CrashDumps `.dmp`。

证据：本机隔离证据目录保存 `owner-app.log`、`member2-app.log`、`member2-server.log` 与 F2 只读核对记录；日志及数据库未随本报告上传。原始 QA 库和真实客户数据未动。

账号切换后只读确认：原合成老板库仍有 13 位客户；新登录业务员使用单独的空白本机账号目录，未改写老板客户库。
