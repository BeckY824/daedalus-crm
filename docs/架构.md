# 架构说明（给想改代码的人）

一页纸讲清楚：代码按什么分、一次 AI 提问怎么走、想加东西该改哪几个文件。
起环境、跑测试见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 一句话

Next.js（App Router）+ antd + Prisma/SQLite。同一份代码跑三种形态：

| 形态 | 怎么跑 | 区别在哪 |
|---|---|---|
| 自部署 | `docker compose up -d` | 一个库，账号在业务库里 |
| 托管版 | `MULTI_TENANT=1` | 一个控制面库（`prisma/control.prisma`）管账号，每个工作区一个 SQLite（`src/lib/tenant/`） |
| 桌面端 | `desktop/`（Electron）起一个本地 Next 服务 | 数据在本机；账号和模型走云端（`src/lib/desktop/cloud.ts`） |

## 目录分工

```
src/app/(app)/<模块>/     每个模块一个目录：page.tsx 取数（服务端）、XxxView.tsx 画（客户端）、actions.ts 写（Server Action）
src/app/api/              少数 HTTP 接口：AI 流式回答、桌面端、模型网关、MCP、健康检查
src/app/admin/            托管版运营台
src/components/           全站共用的件：AppShell（壳）、DataList（所有列表）、AiDock（右侧 AI 面板）、ProposalCard（建议卡）…
src/lib/agent/            AI 助手：run.ts 是循环，tools.ts 是工具箱，proposals.ts 是建议卡
src/lib/llm.ts            怎么跟模型说话；llm-config.ts 是 Key / 接口 / 模型从哪来
src/lib/import/           Excel / CSV / 粘贴导入的纯函数（解析、认列、合并）
src/lib/tenant/           托管版：多工作区、账号、AI 次数账本
prisma/schema.prisma      业务表；migrations/*.sql 是线上增量（只增不改，见 migrations/README.md）
desktop/                  Electron 壳：本地服务、更新、提醒、MCP 桥
tests/  e2e/              单测（vitest）/ 端到端（playwright）
```

写操作的规矩只有一条：**界面和 AI 走同一个 Server Action**。AI 不直接写库，见下一节。

## 一次提问怎么走

```
AskBox / AiDock ──► /api/ai/stream ──► lib/agent/run.ts
                                        │ 1. intents.ts 命中常见问法 → 直接跑工具，跳过模型挑工具
                                        │ 2. 否则让模型挑工具（原生 function calling；不支持时退回 JSON 协议）
                                        │    tools.ts 执行，只读；propose_* 只往「建议卡」里放东西
                                        │ 3. 最多 6 步后流式写最终回答
                                        ▼
                          TurnView 渲染回答 + ProposalCard
                                        │ 人点「确认」
                                        ▼
                          dashboard/apply.ts ──► 原有的 saveCustomer / saveFollowUp / … （同样的校验和留痕）
```

页面上下文：`lib/ai-context-page.ts` 把「人在哪一页、这一页列着谁」变成一句话带给模型；
列表页的名字由 `DataList` 登记、记录页的名字由 `RecordView` 登记（都在 `lib/page-rows.ts`）。

## 扩展点

### 加一个 AI 工具（让助手多会查一样东西）

1. `src/lib/agent/tools.ts`：在 `TOOLS` 里加一项（说明、参数、执行器）。**只读**；要写数据就做成 `propose_*`（见下）
2. `src/lib/agent/schemas.ts`：在 `只读SCHEMAS` 里给它的参数写 JSON Schema。没写，模型看不见这个工具
3. `src/lib/agent/step-summary.ts`：过程条上那句人话（「查了 3 条跟进」）
   写进 `只读SCHEMAS` 的工具会自动开给 MCP（Claude Code / Codex 连进来时也能用）；建议卡那几个在 `建议SCHEMAS`，不对外

`tests/agent-schemas.test.ts` 会核对这三处对得上，漏了会红。

要让 AI 能「提议写入」：在 `lib/agent/proposals.ts` 加一种 `ProposalKind` 和校验，
`tools.ts` 用 `proposeTool(...)` 开出工具，`dashboard/apply.ts` 里接上确认后调哪个 Server Action。

### 加一个行业预设

`src/lib/business-config.ts` 的 `BUSINESS_PRESETS` 加一项：业务简介（进 AI 提示词）、
「客户」叫什么、三个档案字段的名字、下拉选项、状态的显示名。预设只是填表的快捷方式，
套用后设置页里每一项还能自己改；**不要**为某个行业在代码里写 `if`。

### 接一个模型

OpenAI 兼容的接口不用改代码：设置 → AI 接入 填地址、Key、模型名，或者设环境变量
`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`。读取顺序在 `src/lib/llm-config.ts`。
模型的怪癖（不认 thinking 参数、把工具调用写成文本）在 `src/lib/llm.ts` 和 `llm-dsml.ts` 里探测和兜底。
新增一种 AI 功能（为了记账）只改 `src/lib/ai-features.ts`。

### 加一个列表页

1. `src/app/(app)/<模块>/page.tsx` 取数，`XxxView.tsx` 用 `components/DataList` 画（筛选、分页、批量、空态都在它里面；
   筛选写进地址栏用 `lib/url-filters.ts` 的 `useUrlFilters`，搜索框用 `components/ListSearch`）
2. `src/components/AppShell.tsx` 的左栏加一项
3. `src/lib/ai-context-page.ts` 的 `一级` 加这一页的说法和「这一页的数据用哪个工具查」

`tests/one-table.test.ts`（列表页必须走 DataList）和 `tests/ai-context-page.test.ts`（左栏每一项都有 AI 上下文）会拦住漏掉的。

## 几份必须一致的清单

这个项目反复栽在「两处必须一致、改了一处忘了另一处」上：不报错，功能只是像没写一样。所以每一份都有守卫用例：

| 清单 | 守卫 |
|---|---|
| `desktop/package.json` 的 `files` 白名单 | `tests/desktop-shell.test.ts` |
| 工具 ↔ `schemas.ts` ↔ `step-summary.ts` | `tests/agent-schemas.test.ts` |
| 色值只许写在 `globals.css` 的 `:root` 和 `lib/palette.ts` | `tests/design-tokens.test.ts` |
| 动效曲线和时长只许用 token | `tests/motion-tokens.test.ts` |
| 动效的 JS 数值只许写在 `lib/motion.ts`，且和 `globals.css` 的 `:root` 逐值一致 | `tests/motion-tokens.test.ts` |
| 左栏每一页都有 AI 上下文和查询工具 | `tests/ai-context-page.test.ts` |
| AI 功能名单 ↔ 本月用量表 | `tests/settings.test.ts` |
| 主题：`lib/appearance.ts` 的 `主题表` ↔ `src/app/skins/<key>.css` ↔ `layout.tsx` 的 import；主题文件里的 token 名 ↔ `globals.css` 的 `:root`；`skins/shared.css` 的 `--ant-*` ↔ antd 真有的变量、`.css-var-dd` ↔ `lib/theme.ts` 的 `ANTD_CSS_VAR_KEY` | `tests/skins.test.ts` |
| 主题的动效：时长只落四档（90/120/180/320，落印 ≤480）、曲线只写在 token 块、过渡一律 `var(--ease*)`（无限循环的环境动画除外） | `tests/motion-tokens.test.ts` |

## 命名

业务概念用中文标识符（`负责人候选`、`可选客户`、`刷新商机`），框架和通用概念用英文（`saveCustomer`、`DataList`）。
照旧就好，不用统一成一种。注释写「为什么」，尤其是踩过的坑和日期——那是这份代码最值钱的部分。
