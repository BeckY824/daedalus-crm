# 桌面端：安装与更新

面向使用者。想知道它是怎么做出来的，看 [desktop/README.md](../desktop/README.md)。

## 装

1. 下载 `Daedalus CRM-<版本>-arm64.dmg`
2. 打开 dmg，把「Daedalus CRM」拖进「应用程序」
3. 双击打开

**第一次打开会被系统拦下**，提示「无法打开，因为无法验证开发者」。这是正常的：
我们没有买 Apple 的开发者签名（99 美元/年）。放行一次，以后就不会再问：

> 系统设置 → 隐私与安全性 → 往下翻到「安全性」→ 看到「已阻止使用 Daedalus CRM」
> → 点「仍要打开」→ 再确认一次

macOS 15 之后，右键点图标选「打开」那招已经不管用了，只能走上面这条。

如果提示的是「应用已损坏，应该移到废纸篓」，那不是放行的问题——多半是下载没完整，
重新下一次。

> 只有 Apple 芯片（M 系列）的包。Intel Mac 暂时没有。

## 第一次打开会发生什么

- 先弹一个登录窗：用邮箱注册一个免费账号（窗里有「注册新账号」，会打开浏览器到注册页），注册完回来登录
- 登录后在你的机器上建一个数据库，装一套空的 CRM，进主界面。账号只用来记 AI 次数，数据不上传
- 数据全部在 `~/资源库/Application Support/DaedalusCRM/data/crm.db`。
  **备份用菜单里的「备份数据库…」**，不要直接拷这个文件——应用开着的时候库走的是
  WAL，直接拷走的文件可能缺最近的写入。菜单会用 SQLite 自己的备份接口拷出一份
  完整、独立、验过的库。恢复：退出应用，把备份文件改名成 `crm.db` 放回上面那个位置

## 出了问题

- **应用菜单 → 帮助 → 复制诊断信息**：版本、系统、模式、数据目录，一段文字，贴到 issue 里
- **帮助 → 反馈问题…**：打开 GitHub 的新 issue 页，诊断信息已经填在正文里
- **帮助 → 打开日志文件夹**：`logs/server.log` 是本机服务的输出，`logs/app.log` 是应用本身
  没接住的错误。报 bug 时把这两个一起附上
- 应用自己崩了会弹一个框，能直接「复制错误」——那段文字和 `app.log` 里的是同一份

## 要用 AI 的话

登录时用的那个账号自带免费次数（注册送 30，每天登录补 3），不用再做什么。

- 数据仍然只在你自己机器上，登录只是为了调模型
- 免费次数：注册送 30 次，之后每天再送几次，菜单里能看还剩多少
- 想用自己的模型 API Key：在应用里「设置管理 → AI 接入」填，填了就不走我们的额度

没登录也能用，只是 AI 那些入口不出现，CRM 其余功能一样不少。

## 团队一起用

桌面端的数据是这台机器自己的，同事看不到。团队要共用一份数据，
在菜单里「连接服务器」填你们自己部署的那台机器的地址——部署方式见
[docs/部署.md](部署.md)。切过去不会动本机的数据，切回来还在。

## 更新

**不用你做什么。** 应用启动后和之后每 6 小时会自己查一次；有新版就在后台下载、核对。
下完之后，左边侧栏底部出现一个蓝色按钮：**「重启以更新到 x.y.z」**。点它，应用停掉本机服务、
把新版换到原位、自动重启——几秒钟。不弹对话框，不用去官网，不用拖文件，
也**不会再被 Gatekeeper 拦**（那一关只在第一次从浏览器装的时候过一次；应用自己复制的文件不带隔离标记）。
数据在另一个目录，不受影响。

下载中侧栏会显示「正在下载更新 42%」；失败了变成「更新失败，点击重试」。
菜单里「检查更新…」可以立刻查一次，已是最新会告诉你一句。

它做的事：下载 dmg 到数据目录的 `updates/` → 核对 sha256（和 GitHub Release 上记的一致）
→ 校验新包的签名 → 停掉本地服务 → 把旧的应用改名成 `.app.old`、新的换到原位 → 重启。
任何一步失败都会退回去，旧版照样能用。上次留下的 `.app.old` 在下次启动时清掉；
上次下好没装的包会直接复用，不重下。

两种情况下按钮是「有新版本，去下载」而不是「重启以更新」：还在安装镜像里直接双击运行的
（先拖进「应用程序」）；「应用程序」文件夹没有写权限的机器。

为什么不用系统自带的自动更新：macOS 那套（Squirrel.Mac）要求新旧两个包是同一张
Developer ID 证书签的，我们决定不买开发者账号（2026-09-16），只有免费的临时签名。
自己换文件不经过它，签名不是障碍。

### 发版的人要做的事

「检查更新」按顺序查两个地方，任一命中即可：

1. `https://ai-daedalus.com/desktop/latest.json`
   ```json
   {
     "version": "0.23.0",
     "url": "https://ai-daedalus.com/download.html",
     "dmg": "https://github.com/BeckY824/daedalus-crm/releases/download/v0.23.0/Daedalus.CRM-0.23.0-arm64.dmg",
     "sha256": "…（GitHub Release 资产的 digest，deploy/latest-json.py 自动抄）",
     "notes": "这一版改了什么"
   }
   ```
2. GitHub 上最新的 Release（`tag_name` 当版本号）

打 tag 会触发 CI 打包，并把 dmg 挂到同名 Release 上，所以第二条通常自动就是对的。
自家那份 JSON 是给「想控制放量节奏」用的：它优先级更高，改它就能立刻让所有客户端看到新版。
