# Sam 20261013 补充复测后的整改

来源：`codex/windows-0.46.15-test/docs/Windows-0.46.15-20261013-复测补充记录.md`，原报告保存在工作区。6b6eeab 安装包及两份已交付 ZIP 保持不可变；本轮新候选仍公开显示 0.46.15。

## 本轮要求

- 已验收：普通桌面三次冷启、日期、业务员应用内范围与 AI 表述；不把它们当作所有 A–H 手工项通过。
- E2/E3：实际点击未到 JS。修正 Windows 激活入口，须覆盖安装目录、横幅、操作中心、最小化、多隔离实例及账号切换。仅模拟 JS click 不算实机通过。
- 端口：Windows 保留端口导致旧 .port 的 listen EACCES 时，自动重新分配；文件/目录权限错误继续明确报错。
- F2：用户已选择业务员设备只同步本人及公海资料，老板同步全队。原“全队复制、应用内过滤”边界停止作为验收标准。

## 端侧隔离实现顺序

1. 增加版本化、按客户/归属分组的加密同步包；云端只保存必要的编号、负责人、公海状态等授权元数据，不解密姓名、电话、备注和业务内容。授权由认证账号和服务端归属索引决定，不信任客户端声明自己是老板。
2. 按当前权限提供同步目录及密文批次，业务员不接收他人私客包。禁止旧客户端通过旧全量接口绕过；返回明确的升级说明。保留团队加密及移除成员后的换钥匙机制。
3. 老板先迁移：冻结旧推送、追齐历史、保留老板备份，生成按范围的完整起点并启用新协议。业务员升级后发送本人未上传改动、清理非本人/非公海客户及关联记录、同步日志中的整行副本；不向云端传播本机清理删除。
4. 入队、新设备、转交、公海领取、联系人改归属要补齐新获权限资料，撤销失去权限资料；游标不能越过未成功接收的包。关联外键不能迫使客户端接收隐藏客户，字段合并和删除墓碑须继续成立。
5. 恢复旧备份、离线重连、退出/移出也应用范围规则。保留用户本人未上传改动；权限变化时不得静默丢失。升级前已经落到旧设备/手工备份中的资料无法从技术上收回，迁移说明如实标注。

## Windows 通知方向

使用 Windows 支持的协议激活，将点击交给原发送实例的一次性入口；URI 只含随机编号，不含客户/账号/路径/会话凭据。接收入口不打开默认账号库、不接受外部路由字符串；清空通知、到期和换账号后编号失效。保留现有导航确认与超时回退。新增入口需通过真实 Windows 协议分发验证；最后由 Sam 真实点击收口。

## 必须通过的关卡

- 原始失败证据保留；相关单测与真实独立服务联测先通过，再完整 CI。
- 业务员直接读取 SQLite、同步 HTTP、导出、搜索、AI、备份均无其他私客；修改本机角色或伪造已知编号不能从服务器取回/修改老板私客。
- 本人/渠道负责人、公海、两业务员对照、老板全队；领取/转交后失权；联系人未归属与改归属；通用签约/外贸订单；离线不同字段合并及恢复/退队。
- 老版本安全拒绝、老板先迁移、未上传改动、重复请求/断点/坏包/钥匙更换、另一设备加入；不重注册真人账号。
- 最终 Mac 原生验证、Windows 整包与 G2、源码/哈希一致；服务器迁移须先备份并验证回退方案。
- Sam 只收到新候选完整安装包及集中复测 MD。正式 release/feed 与合并继续等待必要手工验收。

## 实现进度（wip/scoped-sync-handoff，2026-10-13 接手审查后）

- 密文 v4：AAD 绑定团队、推送设备、eventId、外层元数据摘要；接收端再逐项核对内层与外层、父链只能指向本机有权记录。
- 灰度：服务端 `CRM_SCOPED_SYNC=1` 才能开始迁移；已迁移团队即使关开关也不回落全队包。桌面端老板也须设同名变量才会发起迁移。生产 compose 未改。
- 老板先迁移：本机备份 `backups/before-scoped-sync-migration.db` → 旧流推完拉齐 → 冻结 → 追到 fence → 起点落盘 `scoped-sync-migration-baseline.json` → 分块推（可断点续） → commit 按服务端新落库条数核对。
- 业务员：每轮推 → 目录 → 清理失权副本 → 按范围拉。失权的未上传改动进 `_sync_scope_conflict`（更新只留本人改的列），界面经 `团队状态().范围.冲突` 显示，退出团队也不删。

### 残留边界（不删用户全部历史）

清理只作用于当前账号 `crm.db` 里的业务表、同步日志/字段钟/墓碑/跳过记录及导入撤销快照（ImportRow）。以下**不删**，只在迁移说明里如实标注：
- 自动/手工备份文件（`backups/`、`daily-*.db`）：升级前生成的可能含全队数据，技术上无法收回；
- AI 对话历史（AiConversation/AiMessage）：只统计引用了失权客户编号的条数（`清理.AI残留`）供界面提示，由用户自行决定是否删除；
- 冲突表：保存本人改动，由老板核对后人工处理。

### 取舍：记录转入范围时不给历史（2026-10-13 决定：隐私优先）

记录改归属（客户转交/领取、联系人等改挂父记录、进出公海）后，服务端把该记录（及其子记录）的路由版本推进到这一批。
非老板只从「改归属之后的第一个当前状态起点」开始拉：起点由做出改动、且仍有权的设备立刻补发（字段钟快照，`baseline`），
失败会记在 `.team.json` 的 `snapshotPending` 下一轮重补。新获权的业务员拿得到当前完整资料和之后的改动，
**拿不到这条记录不在他范围时的历史密文**（例如联系人挂在老板私客下时的改名、旧父客户编号）。
代价：新负责人看不到转入前的逐条改动轨迹（操作日志不随之转移）；老板端历史完整不变。控制面新增表 `SyncScopedBaseline`（020，只加表）。
