# 部署

一个实例一个团队。数据是一份 SQLite 文件，放在 Docker 卷 `/data` 里，归你自己。

## 一条命令

```bash
docker run -d --name crm -p 3000:3000 -v crm-data:/data --restart unless-stopped ghcr.io/becky824/daedalus-crm
docker logs crm | grep 初始密码
```

镜像有 amd64 与 arm64。什么都不用配：

- **会话密钥**首次启动自动生成，存在 `/data/.auth-secret`，之后复用。它同时用于加密 AI Key，所以搬机器时把 `/data` 整个带走
- **初始密码**首次启动随机生成，只在那次日志里打印一回。想自己定，传 `-e INIT_PASSWORD=你的密码`
- 时区默认 `Asia/Shanghai`，改用 `-e TZ=`

## 用 compose

把仓库里的 `docker-compose.yml` 拿下来（或整个仓库 clone），然后：

```bash
docker compose up -d
docker compose logs crm | grep 初始密码
```

可选项写在 `.env` 里，样例见 `.env.example`；都不写也能起。

## 加 HTTPS

需要一个已解析到这台机器的域名（没有域名可用 `1.2.3.4.sslip.io` 这类通配 DNS）。`.env` 里：

```
DOMAIN=crm.example.com
COOKIE_SECURE=true
```

然后：

```bash
docker compose -f docker-compose.yml -f docker-compose.caddy.yml up -d
```

Caddy 自动申请并续期证书，应用不再直接暴露 3000。`COOKIE_SECURE=true` 之后只能经 https 登录。

## 升级

```bash
docker compose pull && docker compose up -d      # 有 Caddy 就带上两个 -f
```

迁移自动跑：容器每次启动按顺序执行 `migrations/*.sql`，每条幂等，重跑无副作用。
迁移只增不改不删，所以旧版本镜像也能跑在新库上，回滚就是换回旧 tag：`image: ghcr.io/becky824/daedalus-crm:0.2.0`。

## 备份与恢复

```bash
./scripts/backup.sh                                     # → backups/crm-<时间>.db
CONFIRM=RESTORE ./scripts/restore.sh backups/crm-xxx.db  # 会先自动备份当前状态
```

**不要直接复制 `crm.db`**：数据库跑在 WAL 模式，最近的写入还在 `crm.db-wal` 里。脚本用 `VACUUM INTO` 拿一致性快照，
恢复时先停容器、连 `-wal` / `-shm` 一起清掉。用 `docker run` 起的实例把脚本里的 `docker compose exec -T crm` 换成 `docker exec -i crm` 即可。

## 账号与密码

登录用**用户名**，不是邮箱。首启建三个账号：`admin`（管理员）和两个演示销售 `zhangsan` / `lisi`，密码相同；
演示账号用不上就在「设置管理 → 团队成员」停用。日常增删成员在界面里做。

忘了管理员密码：

```bash
docker compose exec -T -e RESET_PASSWORDS=1 -e INIT_PASSWORD=新密码 crm node seed.js
```

## 清空数据重来

不可逆，先备份：

```bash
docker compose exec -T -e CONFIRM=RESET -e INIT_PASSWORD=新密码 crm node reset-data.js
```

## 从源码构建

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

小内存服务器（2G）跑 Next 构建会 OOM，那就在本机构建后 `docker save | ssh ... docker load`，或者直接用预构建镜像。

## 所有环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 3000 | 对外端口（仅 compose） |
| `AUTH_SECRET` | 自动生成 | 会话签名与 AI Key 加密的密钥，≥32 位 |
| `INIT_PASSWORD` | 自动生成 | 首次启动 admin 的密码；库已存在时忽略 |
| `COOKIE_SECURE` | false | 只经 HTTPS 访问时设 true |
| `TZ` | Asia/Shanghai | 服务器时区，要与使用者一致 |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 空 | AI 接入的兜底；界面里填的优先 |
| `DOMAIN` | — | 仅 Caddy 叠加层 |
| `REBUILD_DB` | — | 设 1 时启动前备份并重建库，表结构大改时用 |

## 表结构变更

改了 `prisma/schema.prisma`，存量库要一条幂等迁移放进 `migrations/`（规则见 `migrations/README.md`）。
真要重建，`REBUILD_DB=1` 启动一次：旧库先备份到 `/data/pre-rebuild-<时间>.db`。

## 并发与性能

SQLite 已切 WAL 模式，启动时设 `busy_timeout=5000`，几人到二十人并发够用。
客户端路由缓存 60 秒：别人的改动最多滞后 60 秒出现在已缓存页面，自己的改动立即可见。
