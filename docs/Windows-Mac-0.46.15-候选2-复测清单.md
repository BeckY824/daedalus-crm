## A. Windows 通知点击（E2/E3 复测）

前提：用完整安装版（协议激活只在安装版注册）。每一项点击后 `app.log` 必须依次出现 `activation-received` 和 `clicked`，并跳到对应页面；只有 `shown`/`banner-closed` 视为失败。

| # | 场景 | 期望 |
|---|---|---|
| A1 | 横幅弹出时直接点 | 跳转；日志有 activation-received、clicked |
| A2 | 横幅消失后从操作中心（通知中心）点 | 同上 |
| A3 | 窗口最小化时点 | 窗口恢复并跳转 |
| A4 | 多个隔离实例（不同数据目录）同时运行，各发一条 | 每条只回到发出它的那个实例 |
| A5 | 老板账号发通知后切换到业务员账号，再点旧通知 | 不打开老板资料；日志为 stale-click-ignored 或通知已被清除 |
| A6 | 到点提醒（E3）出现后点击 | 跳转到提醒对应记录 |
| A7 | 检查日志与注册表 | 日志/URI 中不含客户姓名、电话、路径；`HKCU\Software\Classes\daedalus-crm-notify` 存在 |

## B. 保留端口恢复

1. 用 `netsh interface ipv4 show excludedportrange protocol=tcp` 找一个保留范围内的端口 P。
2. 关闭应用，把数据目录里的 `.port` 改成 P，启动。
3. 期望：正常打开，`.port` 被改成新端口；`app.log` 不再出现 `listen EACCES`。
4. 对照：把数据目录设为只读（写不了 `.port`），应明确报错而不是静默换端口。

## C. 0x80000003 复现尝试

1. 按上轮方式从工具终端（PowerShell / Windows Terminal）启动独立业务员实例，重复 5 次；再从资源管理器启动 5 次。
2. 记录每次是否出现 `unknown software exception (0x80000003)`、地址、`server.log` 是否有「服务启动超时」。
3. 检查 `%LOCALAPPDATA%\CrashDumps` 是否有新的 `.dmp`，有则一并提交。本候选未针对此问题修改，只求复现条件。

## D. 范围同步（只在测试服务器 + 合成团队上做）

按 `docs/范围同步启用操作手册.md` 执行，不要动生产。

| # | 步骤 | 期望 |
|---|---|---|
| D1 | 备份测试服务器控制库和 SYNC_DIR，`integrity_check` 为 ok | 备份文件存在 |
| D2 | 开关关闭时部署 | 旧团队照常同步；scoped 接口返回 404 |
| D3 | 服务器设 `CRM_SCOPED_SYNC=1` | 未升级/未迁移时业务员同步被拒并提示 |
| D4 | 老板电脑以 `CRM_SCOPED_SYNC=1` 启动并同步；推送起点途中拔网线，恢复后再同步 | 中断后提示「下一轮继续」，恢复后完成；`backups/before-scoped-sync-migration.db` 存在，`scoped-sync-migration-baseline.json` 完成后消失 |
| D5 | 业务员升级后同步，只读打开 `crm.db` | 搜不到老板私客姓名/电话（含 `_sync_log`、`ImportRow`）；本人客户和离线改动都在；首页客户数正确 |
| D6 | 老板把客户转给业务员 / 业务员领取公海客户 / 老板把联系人改挂到业务员客户下 | 业务员看到当前资料；看不到转入前的历史改动过程 |

| D9 | 业务员伪造已知编号（改本机角色/库）再同步 | 取不回、改不了老板私客 |
| D10 | AI 历史提示 | 若以前问过老板私客，设置 → 团队显示「AI 对话历史里有 N 条」提示，历史未被删除 |
