## 走查中发现并已修的三处

1. **手机上每个页面都横向溢出 66px**。侧栏在窄屏只收到 80px 而不是 0。
   销售从微信点进来第一眼就是一条横向滚动条。已改。
2. **数据首页有三处编出来的数字**：预测销售额的「较上月 ↑ 18.6%」是写死的
   （零数据也显示）；「新增客户」的涨跌写死 ↑ 和绿色还套了 `Math.abs`，
   下降会显示成上升；三条小曲线是写死的数组。已改为按最近 8 周真算。
3. **业绩排行的姓名压在进度条上**（格子固定 92px 且不裁剪）。已改。

## 需要你确认的一处口径

**商机管道的「赢单成交」永远是 0**。管道只统计 `status = OPEN` 的商机，
而阶段推到「赢单成交」时状态必然变成 `WON`——所以漏斗最后一档结构性为零。
是要把已赢单的算进最后一档，还是干脆不在漏斗里画这一档？这是口径问题，我没擅自改。

# 还需要人来做的

机器判定不了的三类。**建议随 UAT 一起做，边用边记。**

## 一、业务正确性（只有你们知道对不对）

- [ ] 归属规则（推荐人 / 渠道归属 / 渠道负责人三者独立）与实际提成规则一致吗
- [ ] 「渠道归属取推荐链往上第二代」这条规则，在你们的分成里是这么算的吗
- [ ] 跟进状态的 8 个档位，够用吗？有没有你们常用但缺的
- [ ] 决策状态的 6 个档位同上
- [ ] 学员表单的字段够不够？缺什么、哪些其实从来不填
- [ ] 线索来源的 7 个选项贴合你们的获客渠道吗
- [ ] 复盘页的统计口径，是你们对账时真正看的那几个数吗

## 二、文案与易用性（要用的人自己判断）

- [ ] 有没有哪句话是「开发说的话」而不是「销售听得懂的话」
- [ ] 并发冲突的提示（「有人和你改了同一项」）看得懂该怎么办吗
- [ ] 删除保护的提示（「推荐了 N 人，N 人的业绩归属于他」）说清楚了吗
- [ ] 签约重复录入的确认框，能让人做出正确判断吗
- [ ] 删除最后一笔签约时的三个回退档位，措辞分得清吗
- [ ] 表单字段的排布顺序，符合你们的录入习惯吗
- [ ] 手机上筛选条件占了整整一屏才看到数据，能接受吗

## 三、机器替代不了的环境

- [ ] **微信内置浏览器**打开（最重要——销售大概率从微信点链接进来）
- [ ] 真机 iPhone / 安卓浏览器
- [ ] 办公室实际网络下的加载速度

## 记录方式

- **拦路**：影响正常使用，上线前必须修
- **别扭**：能用但每次都难受，排期修
- **建议**：可做可不做

写清楚：**哪个页面、做了什么、期望看到什么、实际看到什么**。
同一个问题被两个人分别提到，说明它比看上去更严重。
